# Разработка и тестирование

Технические подробности, которые не нужны обычному пользователю: режим разработки,
логирование, автообновление, тесты и диагностика.

## Режим разработки (`dev.flag`)

Включается любым способом:

- файл-маркер `dev.flag` в рабочем каталоге рядом с программой;
- аргумент запуска `--dev` или `--updateDemo`;
- системное свойство `-Dreminder.dev=true`.

У файла `dev.flag` два режима.

### 1. Пустой маркер

Достаточно создать пустой файл `dev.flag` — включится dev-режим (например, диалог
обновления с демо-описанием). Источник обновления при этом не задан, поэтому кнопка
«Обновить» выключена (в подсказке будет пример, как задать источник).

### 2. Симуляция реального обновления

Добавьте в `dev.flag` строки:

```
updateFrom=C:\path\to\TaskReminder-9.9.9-win-x64.zip
updateVersion=9.9.9
```

- `updateFrom` — путь к локальному архиву (zip для Windows, tar.gz для Linux) или URL;
- `updateVersion` — версия, которую «увидит» приложение (должна быть новее текущей).

Для локального файла sha256 считается автоматически. Также можно задать значения
системными свойствами: `-Dreminder.updateFrom=...`, `-Dreminder.updateVersion=...`,
`-Dreminder.updateSha=...`.

Файл `dev.flag` — **обычный текст** (UTF-8). Сохранять как RTF/Word нельзя. BOM
(маркер кодировки в начале файла) теперь переносится — файлы из Блокнота/`Set-Content`
тоже работают.

Пример для запуска из исходников: создайте `dev.flag` в корне проекта (там же, где
`gradlew`) и выполните `./gradlew run`.

## Логирование (`log.flag`)

Включение (любой способ):

- файл-маркер `log.flag` в рабочем каталоге;
- аргумент `--log`;
- системное свойство `-Dreminder.log=true`.

Логи пишутся в `logs/` рядом с программой (при отсутствии прав — во временный каталог),
по файлу `TaskReminder-yyyy-MM-dd_HH-mm-ss.log` на запуск:

- шапка: версия/commit, ОС, Java, локаль, `user.dir`, `app.dir`, флаги;
- строки `[дата время] [тег] (поток) сообщение`;
- сюда же попадают все выводы `System.out/err` и стектрейсы;
- при достижении 10 МБ начинается новый файл; хранятся последние 100 файлов.

Сбои логирования безопасны — работу приложения не прерывают.
Код: `app/LogConfig.java`, `util/Log.java`.

## Автообновление

Две программы:

1. **Приложение** проверяет релизы GitHub, выбирает архив под текущую ОС, скачивает его
   с прогрессом и проверяет sha256.
2. **Апдейтер** (`updater/`, Go) запускается из временной копии, дожидается выхода
   приложения, распаковывает архив, заменяет `app/`, `runtime/`, `updater/` и exe
   с бэкапом и откатом, сохраняет данные и `language/`, затем перезапускает приложение.

Тестирование:

- проще всего через `dev.flag` (см. выше) — указывает на локальный архив;
- лог апдейтера: `%TEMP%\TaskReminder-autoupdate.log` (Windows) или `/tmp/...`;
- апдейтер можно проверить отдельно, запустив бинарник с аргументами
  `-archive <архив> -dir <каталог> -exe <имя>` (см. `updater/main.go`).

Важно: автообновление работает только начиная с версии, в которой уже есть папка
`updater/`. Более старые версии обновляются вручную («Скачать zip»).

## Тестирование

- Все тесты и сборка: `./gradlew clean build` (Windows: `.\gradlew.bat build`).
- Отдельно тесты: `./gradlew test`.
- Апдейтер:
  ```
  cd updater
  go vet ./...
  go build -o autoupdater.exe .            # Windows
  GOOS=linux GOARCH=amd64 go build -o autoupdater .   # Linux
  ```

Полезные тесты: паритет языковых ключей (`LanguageKeyParityTest`), FXML
(`FxmlResourcesTest`), разбор `dev.flag` с BOM (`DevModeTest`), загрузка/проверка
архива (`UpdateDownloaderTest`), расписание проверки обновлений (`UpdateScheduleTest`).

## CI

- `.github/workflows/ci.yml` — тесты на push в `main` и на pull request.
- `.github/workflows/release.yml` — по тегу `v*`: Windows (сборка Go-апдейтера,
  app-image, zip) и Linux (tar.gz), публикация GitHub Release.
- `.github/workflows/linux-build.yml` — ручная сборка Linux (`workflow_dispatch`).

## Устранение неполадок

- **Где лог:** `logs/` рядом с программой (или во временном каталоге, если нет прав).
- **Приложение не запускается до старта JVM** (нативный лаунчер, отсутствие GTK/glibc
  на Linux): наш лог тут не поможет. Запустите `bin/TaskReminder` из терминала, чтобы
  увидеть ошибку; проверьте зависимости системы.
- **`dev.flag` не срабатывает:** флаги читаются из рабочего каталога. Если приложение
  запущено ярлыком с другой «Рабочей папкой», флаг рядом с exe может быть не найден —
  запускайте из папки программы или укажите «Рабочую папку» в ярлыке.
- **Кнопка «Обновить» выключена в dev-режиме:** не задан `updateFrom` или локальный
  архив не найден — наведите на кнопку, подсказка покажет пример/путь.
- **Экспорт в Excel пишет `ERROR StatusLogger ...`:** это служебное сообщение Apache POI
  (нет реализации Log4j2); на работу не влияет.
