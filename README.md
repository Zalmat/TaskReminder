# 📋 Учет рабочего времени (В базе создано через ИИ)

Десктопное приложение для учета рабочего времени с поддержкой дневного и недельного режимов.

<p align="center">
  <img src="docs/images/mascot.png" alt="Маскот TaskReminder" width="220">
</p>

## 🚀 Основные возможности

### 📅 Дневной режим
- Быстрое добавление задач с указанием часов
- Автоматический контроль дневного лимита (8 часов)
- Редактирование и удаление записей
- Визуальная индикация оставшегося времени

### 📊 Недельный режим
- Обзор всех задач за неделю
- Редактирование часов двойным кликом по ячейке
- Автоматический подсчет итогов по дням и неделе
- Поддержка праздничных дней (нередактируемые)
- Визуальный контроль лимитов (48 часов в неделю)
- Фиксированная высота строк и центрирование текста без обрезки
- Подсветка задач без часов и подтверждение при уходе из недели, смене даты, выходе из приложения или установке обновления

### ⏰ Напоминания
- Создание напоминаний с указанием времени
- Настройка ежедневного повторения
- Управление активностью напоминаний
- Редактирование и удаление существующих напоминаний

### 🔍 Проверка обновлений
- Кнопка «Проверить обновления» проверяет наличие новых версий через GitHub Releases
- Показывает описание релиза
- Скачивает и устанавливает обновление с проверкой контрольной суммы
- Перед установкой проверяет наличие несохраненных задач недели

### 📂 Загрузка задач из YAML
- Импорт списка задач из YAML файла
- Автоматическое добавление в список задач
- Кнопка «Скачать шаблон YAML» сохраняет пример файла для заполнения

### 📊 Экспорт данных
- Поддерживаемые форматы: Excel (.xlsx), CSV (.csv), JSON, YAML, XML
- Экспорт за выбранный период
- Автоматическое формирование имени файла с датой

### 🪟 Системный трей
- Окно сворачивается в системный трей кнопкой «минимизировать» (иконка генерируется автоматически)
- Выход через диалог окна или меню трея («Открыть» / «Выход»)
- Двойной клик по иконке трея разворачивает окно
- После смены языка приложение корректно перезапускается, трей создается на выбранном языке

### 🎨 Настройки и оформление
- Кнопка-меню (☰) в левом нижнем углу -> «Настройки»
- Переключаемая тема: Светлая / Темная (применяется к окну и всем диалогам)
- «Тип работы по умолчанию» для формы ввода
- Выбор языка интерфейса (русский и английский встроены; немецкий и болгарский - внешние файлы; применяется после перезапуска)
- «Десятичный разделитель» для экспорта: как в системе / точка / запятая
- Автозапуск при входе в систему (свернутым в трей) - в собранной версии (Windows/Linux)
- Кнопка «Открыть папку с программой» (в настройках и в диалоге обновления)
- Настройки сохраняются между запусками
- Для пустых таблиц показывается сообщение «Нет данных»

## 💾 Хранение данных

Основное хранилище - SQLite v2 в рабочем каталоге приложения (там, откуда запускается приложение):

| Файл | Назначение |
|------|-----------|
| `taskreminder.db` | Основная база SQLite: записи, задачи, напоминания, праздники, каталог подсказок |
| `storage.meta.json` | Версия схемы данных (`schemaVersion`) и дата создания |
| `backups/` | Резервные копии перед миграцией |
| `work_entries.json` | Legacy-файл записей; может оставаться после миграции |
| `predefined_tasks.json` | Legacy-справочник задач |
| `reminders.json` | Legacy-файл напоминаний |
| `holidays.json` | Legacy-файл праздников |
| `holidays.json.bak` | Backup старого формата праздников |
| `task_catalog.json` | Legacy-каталог подсказок |

- При первом запуске создается пустая SQLite-база v2.
- Старые JSON-данные автоматически переносятся в SQLite с backup в `backups/pre-migration-v<N>-<timestamp>`.
- Старые `.dat`-файлы сначала переносятся в JSON, затем в SQLite.
- Перед миграцией создается полный backup с `manifest.txt`; хранятся последние 5 backup-каталогов.
- При ошибке миграции выполняется восстановление из backup.
- JSON-файлы остаются для совместимости и отката, но рабочее хранилище - SQLite.
- В релизную сборку файлы данных не попадают: `build-release.ps1` очищает их из каталога приложения.

## 🌐 Языки интерфейса

- **Встроенные** языки (лежат внутри jar): русский (`ru`), английский (`en`).
- **Внешние** языки (файлы в подпапке `language/` рядом с программой): немецкий (`de`), болгарский (`bg`).
  При первом запуске они автоматически распаковываются из jar; существующие файлы не перезаписываются.
- Список языков в «Настройки -> Язык» формируется при запуске сканированием папки `language/`,
  поэтому можно **добавить свой язык**: положите файл вида `fr_lang.yaml` (по образцу существующих) и перезапустите приложение.
- Переключение языка применяется **после перезапуска** (в окне настроек есть кнопка «Перезапустить сейчас»).
- Состояние пакета показывается прямо в списке:
  - `Deutsch` - все в порядке;
  - `Deutsch - Неполный (N/M)` - часть ключей отсутствует, недостающие берутся из английского/русского;
  - `Deutsch - Поврежден` - файл не читается (ошибка YAML), язык не применяется.
- В тултипе языка показывается источник: встроенный пакет или путь к файлу.

Формат файла `language/<код>_lang.yaml` (UTF-8, значения с `{0}` - в кавычках):

```yaml
# machine translation
_language: de
_name: Deutsch
strings:
  app.title: "TaskReminder - Zeiterfassung"
  main.total: "Erfasst: {0} Std."
```

- Для встроенных пакетов поддерживается паритет ключей, он проверяется тестом `LanguageKeyParityTest`.
- Внешний пакет может быть неполным: недостающие ключи автоматически берутся из встроенного пакета, затем из английского/русского.
- Если внешний пакет использует код встроенного языка, его строки дополняют и переопределяют встроенный пакет.
- Ключи `settings.language.source.builtin` и `settings.language.source.file` необязательны и используются только в тултипе.
- `table.empty` - текст для пустых таблиц; его стоит перевести в своем языковом пакете.
- Локаль форматирования чисел и дат определяется по `_language`.

## 📦 Сборка релиза (портативная версия)

Скрипт `build-release.ps1` собирает app-image, zip-архив и контрольную сумму:

```
.\build-release.ps1
```

Результат в каталоге `build\release\`:

```
build/release/
├── TaskReminder/                     # app-image (можно запускать напрямую)
├── TaskReminder-<версия>-win-x64.zip
└── TaskReminder-<версия>-win-x64.zip.sha256
```

- Версия берется из git-тега вида `v1.9.2`; если тегов нет - `1.0.0` + короткий хэш коммита; при сборке из ZIP без git-метаданных - `1.0.0-src`.
- JavaFX jmods: берутся из `$env:JAVAFX_JMODS`, затем из `C:\tools\javafx-jmods-*`; если их нет - автоматически скачиваются с сайта Gluon. Нужен только установленный JDK 17.
- В приложение включен модуль проверки обновлений: для публикации новой версии создайте Release в GitHub (`v1.9.2` и т.д.) и прикрепите к нему `TaskReminder-<версия>-win-x64.zip`.
- Готовая сборка предназначена для **Windows x64**.
- Файлы данных в ZIP не входят: приложение создает их при запуске.

### 🤖 Автопубликация релизов (GitHub Actions)

Workflow `.github/workflows/release.yml` срабатывает **при пуше тега** `v*`:

1. Проверяет файл заметок `release-notes.md`: если он пуст или равен тексту предыдущего релиза - сборка **не запускается** и Release не создается.
2. Собирает проект (gradle + jpackage) и создает Release, прикрепляя `*.zip` и `*.sha256`.

Порядок выпуска версии:

```
git add README.md release-notes.md
git commit -m "Release notes v1.9.2"
git tag -a v1.9.2 -m "v1.9.2"
git push origin main
git push origin v1.9.2
```

Старые архивы релизов при необходимости удаляются вручную.

## ⚙️ Системные требования

- **Java 17** или выше для сборки и запуска из исходников

## 🎯 Лимиты времени

- **Дневной лимит**: 8 часов
- **Недельный лимит**: 48 часов
- При превышении лимитов значения подсвечиваются красным

## 📋 Управление праздниками

- В профиль по умолчанию входят 8 ежегодных официальных праздников:
  - 1 января - Новый год
  - 7 января - Рождество Христово
  - 23 февраля - День защитника Отечества
  - 8 марта - Международный женский день
  - 1 мая - Праздник Весны и Труда
  - 9 мая - День Победы
  - 12 июня - День России
  - 4 ноября - День народного единства
- Дефолтные праздники имеют тип «Праздник», ежегодность «Да» и источник `DEFAULT`.
- Старые пустые записи на этих датах автоматически получают название и ежегодность.
- Дубликаты, возникшие после нормализации, удаляются; пользовательские и импортированные события сохраняются.
- Названия дефолтных праздников сейчас указаны на русском языке.
- Праздничные дни не редактируются в недельном режиме.
- Выходные дни (СБ, ВС) редактируются и могут быть рабочими.
